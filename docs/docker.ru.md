# Сервер и панель в Docker

<!-- // ai-generated: Docker installation, public TLS access and maintenance guide. -->

Образ содержит сервер olcrtc и встроенную веб-панель. Поддерживаются Linux amd64
и arm64. Собирать Go на VPS не нужно.

## Установка

Нужны Linux с systemd, `curl`, `openssl`, `getent` и `ss`. Docker и Compose
установщик проверит; если Docker отсутствует, предложит установку с get.docker.com.

```bash
# // ai-generated: download and start the interactive Docker installer.
curl -fsSL https://raw.githubusercontent.com/cmzmozg/olcrtc/proofkit/scripts/install-docker.sh -o install-docker.sh
sudo bash install-docker.sh
```

Выберите «Установить». Скрипт:

1. Определит публичный IPv4 VPS через внешний сервис.
2. Найдёт сертификаты в `/etc`, `/opt`, `/root/.acme.sh`, `/var/lib/caddy`.
   Из SAN сертификата выберет домен или IP, резолвящийся на публичный IP VPS.
   Проверит срок действия, соответствие имени и закрытого ключа.
3. Предложит найденный адрес и сертификат. Если подходящего сертификата нет,
   выпустит Let's Encrypt для выбранного домена или самого IP. Самоподписанный
   сертификат вместо публичного не создаётся.
4. Сгенерирует уникальный путь из 32 hex-символов и пароль из 48 hex-символов.
5. Запустит образ `ghcr.io/cmzmozg/olcrtc:latest` и проверит HTTPS панели.
6. Настроит таймер продления TLS и разрешит порт панели в активном UFW/firewalld.

В конце появятся адрес вида `https://vpn.example.com:8884/<случайный-путь>/`
и пароль. Они также сохраняются в `/opt/olcrtc-docker/access.txt`, доступном
только root. Запросы вне секретного пути получают 404; вход требует пароль.
Подписки доступны отдельно по `/sub/<токен>`.

Панель слушает `0.0.0.0:8884` по HTTPS и доступна из интернета. Во внешнем
firewall провайдера VPS разрешите этот TCP-порт. Транспорт olcrtc сам подключается
к сервису звонков и дополнительных входящих портов не требует.

## Сертификат VPS и новый выпуск

Существующие сертификаты и ключи не перемещаются и не меняют владельца.
Установщик копирует проверенную пару в каталог данных контейнера. Таймер каждый
час проверяет исходные файлы и перезапускает контейнер, только если пара изменилась.
Продление существующего сертификата остаётся за тем инструментом, который уже
работает на VPS: Certbot, acme.sh, Caddy и т.п.

Для нестандартного расположения или wildcard-сертификата задайте адрес и пути явно:

```bash
# // ai-generated: reuse an existing VPS certificate for an explicitly selected host.
sudo bash install-docker.sh --host vpn.example.com \
  --cert /path/to/fullchain.pem --key /path/to/privkey.pem
```

Домен должен иметь A-запись с публичным IPv4 этого VPS. Если автоматическое
определение IP не подходит, укажите `--ip 203.0.113.10`. Автопоиск не восстанавливает
все домены из DNS по одному IP: он проверяет имена в найденных сертификатах.
Без сертификата предложит публичный IP; свой домен можно ввести в меню.

Для нового сертификата используется отдельный контейнер Certbot. Нужен входящий
TCP/80 из интернета для HTTP-01. Если порт свободен, используется standalone.
Если он уже занят веб-сервером, укажите webroot, из которого этот сервер отдаёт
`/.well-known/acme-challenge/`; существующий веб-сервер установщик не останавливает.

```bash
# // ai-generated: issue a domain certificate through an existing web server.
sudo bash install-docker.sh --host vpn.example.com --webroot /var/www/html
```

Установщик запрашивает согласие с условиями Let's Encrypt и необязательный email.
`--yes` принимает условия и значения по умолчанию. Для IP используются сертификаты
профиля `shortlived` со сроком около шести суток. Сертификаты нового выпуска
продлеваются тем же таймером, проверка выполняется каждый час. Ограничения
HTTP-01 сохраняются при продлении. [Описание IP-сертификатов Let's Encrypt](https://letsencrypt.org/2026/03/11/shorter-certs-certbot/).

Таймер `olcrtc-docker-tls.timer` вызывает только продление сертификата этой
установки. Логи: `journalctl -u olcrtc-docker-tls.service`. После смены сертификата
контейнер перезапускается, активные соединения переподключаются.

## Комнаты и клиенты

Откройте уникальную ссылку, войдите с выданным паролем, добавьте комнату и клиента.
Скопируйте ссылку `olcrtc://` или адрес подписки в приложение. Комнаты и ключи
сохраняются в `data/panel.json` с правами 0600. В конфиге нет постоянного общего
ключа: отключение клиента в панели закрывает его доступ ко всем комнатам.

По умолчанию новые комнаты используют `vkcalls + vp8channel`; провайдер выбирается
при установке. `vp8.olt_disabled: true` отключает экспериментальный olt.
Свойства панели описаны в [panel.ru.md](panel.ru.md).

## Управление

Повторно запустите скрипт и выберите обновление, статус со ссылкой, логи,
остановку или удаление контейнера. Можно вызвать действие явно:

```bash
# // ai-generated: update or inspect the installed Docker server.
sudo bash install-docker.sh --action update
sudo bash install-docker.sh --action status
sudo bash install-docker.sh --action logs
```

Обновление сначала загружает образ, затем пересоздаёт контейнер и проверяет
панель. При неуспешном запуске возвращает предыдущий образ. Конфиг, комнаты,
пароль, путь и ключи не перегенерируются. Удаление снимает контейнер и отключает
таймер, оставляя данные и сертификаты.

Каталог по умолчанию: `/opt/olcrtc-docker`. Для другого используйте `--dir`
при каждом запуске. Одновременно поддерживается одна установка этим скриптом.
Её данные не импортируются из существующего systemd-сервера автоматически.
Для резервной копии сохраните весь каталог установки с правами и владельцами.

## Образ и сборка

Контейнер работает от UID/GID `10001:10001`, с файловой системой образа только
для чтения, без capabilities. Каталог `data` доступен на запись. Используется
сеть хоста, поэтому публикация Docker-портов не нужна.

```bash
# // ai-generated: build the server image locally through the Dockerfile's Mage stage.
docker build -t olcrtc:local .
sudo bash scripts/install-docker.sh --image olcrtc:local --skip-pull
```

`compose.yaml` в корне репозитория позволяет запустить образ вручную после
подготовки `data/server.yaml`, сертификата и каталога с владельцем `10001:10001`.
Установщик создаёт эти файлы сам. Образ включает LICENSE, NOTICE и исходную лицензию.

Workflow `Docker server` проверяет установщик на реальном контейнере, затем
публикует amd64 и arm64 в GHCR. Теги: `latest` и `sha-<полный commit>`.
Пакет GHCR должен быть публичным для загрузки без входа в GitHub.

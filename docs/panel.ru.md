# Веб-панель сервера

<!-- ai-generated: the whole file (panel). -->

Панель встроена в сервер olcrtc: отдельного процесса и фронтенд-сервера нет. Через неё добавляют комнаты, выдают клиентам ключи, ссылки `olcrtc://` и подписки, смотрят состояние комнат и трафик клиентов.

- **Комнаты.** Сервер сидит во всех включённых комнатах одновременно, у каждой свой сервер в том же процессе. Добавленная комната начинает работать сразу, выключенная или удалённая освобождается. Смена ссылки, провайдера или транспорта перезапускает сервер комнаты, переименование нет. Для провайдеров, которые умеют создавать комнаты сами (`salutejazz`), есть кнопка «Создать на провайдере». Для `vkcalls` звонок создают в приложении VK и вставляют ссылку входа `https://vk.ru/call/join/<id>`.
- **Клиенты.** У каждого клиента свой ключ в кольце `crypto.keys` сервера. Ключ подходит ко всем комнатам. Отключённый или удалённый клиент теряет доступ сразу во всех комнатах: его сессии рвутся, а новые не проходят рукопожатие.
- **Ссылки.** Для каждой комнаты клиент получает ссылку в формате [uri.md](uri.ru.md). Подпись `$` у ссылки: «имя клиента / имя комнаты».
- **Подписка.** `https://<адрес>/sub/<токен>` в формате [sub.md](sub.ru.md) отдаёт ссылки на все включённые комнаты. Новая комната дойдёт до клиента при следующем обновлении подписки (`#refresh: 1h`). Подписка лежит вне секретного пути панели и не выдаёт его. «Новая подписка» меняет токен, и старый адрес перестаёт работать.
- **Состояние и трафик.** У комнаты видно, что делает её сервер: в звонке, подключается, переподключается, ошибка (текст ошибки во всплывающей подсказке), выключена. Трафик клиентов считается с запуска сервера.

Комната и ключи из самого конфига (`room.id`, `crypto.key`, `crypto.keys`) продолжают работать рядом с панельными. Комната конфига видна в панели с пометкой «из конфига» и не редактируется. Старые ссылки клиентов поэтому не ломаются, когда на сервере включают панель.

## Настройка

```yaml
mode: srv
auth:
  provider: vkcalls          # провайдер новой комнаты по умолчанию
net:
  transport: vp8channel      # транспорт новой комнаты по умолчанию
  dns: "1.1.1.1:53"
vp8:
  fps: 60
  batch_size: 64
panel:
  listen: "127.0.0.1:8884"
  path: "3f9c1a7d2b8e4c60a1d5e9f2"
  password: "длинный-случайный-пароль"
  store: panel.json
```

| Поле | Значение |
|---|---|
| `panel.listen` | адрес панели `host:port`; пустое значение выключает панель |
| `panel.path` | секретный путь: панель отвечает только на `/<path>/`, остальное получает 404. От 8 символов: латиница, цифры, `-`, `_` |
| `panel.password` | пароль администратора, от 12 символов |
| `panel.store` | файл комнат и клиентов, относительно конфига; по умолчанию `panel.json`. Пишется атомарно, права 0600: в нём ключи клиентов |
| `panel.cert` / `panel.key` | TLS панели; обязательны, если `listen` не loopback |
| `panel.public_url` | база адреса подписки, например `https://vpn.example.com:8884`; без неё берётся адрес, по которому открыли панель |

Панель работает только в `mode: srv` без `profiles`. Без `room.id` и без ключа в конфиге сервер стартует: комнаты и ключи придут из панели. `stats.listen` обслуживает только сервер комнаты из конфига, а счётчик у него общий для всех комнат.

## Доступ

По умолчанию панель слушает loopback, и попасть в неё можно через SSH-туннель:

```bash
ssh -L 8884:127.0.0.1:8884 root@<адрес сервера>
```

После этого откройте `http://127.0.0.1:8884/<path>/`.

Публичной панели нужен TLS (`panel.cert`, `panel.key`): по открытому HTTP панель не запускается. Защита такая:

- секретный путь;
- пароль;
- блокировка адреса на 15 минут после 5 неудачных входов;
- cookie сессии `HttpOnly`, `SameSite=Strict`, а при TLS ещё и `Secure`;
- заголовок `X-Olcrtc-Panel` обязателен для любых изменений;
- строгая CSP, ничего не грузится со сторонних адресов.

Ключи клиентов в списке не показываются, они есть только в ссылках и подписке. Не публикуйте ссылки и адреса подписок: в каждой ссылке ключ клиента.

## Установка

`scripts/build-server.sh` собирает архив для Linux (amd64 и arm64) с бинарником, установщиком и контрольными суммами. На сервере:

```bash
tar xzf olcrtc-server-<rev>-linux-amd64.tar.gz && cd olcrtc-server
sha256sum -c SHA256SUMS
sudo ./install-server.sh
```

Установщик создаёт:

- пользователя `olcrtc`;
- каталог `/etc/olcrtc` (0700);
- конфиг со случайными путём и паролем;
- службу `olcrtc` с ограничениями systemd.

В конце он печатает команду SSH-туннеля, адрес панели и пароль. Опции:

- `--room` добавляет комнату в конфиг;
- `--provider`, `--transport`, `--fps`, `--dns` задают значения по умолчанию;
- `--panel-public --cert --key` открывают публичную панель;
- `--update` обновляет бинарь: делает резервную копию, проверяет службу 10 секунд и откатывает при сбое;
- `--uninstall` снимает службу, а данные оставляет.

Повторный запуск не трогает конфиг, комнаты и клиентов. Туннелю olcrtc входящие порты не нужны, установщик открывает порт только для публичной панели. `scripts/test-install-server.sh` проверяет установщик в контейнере с systemd.

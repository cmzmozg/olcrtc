# Буферы сервера и восстановление VK

<!-- // ai-generated: document server buffer ownership, compatibility and bounded VK recovery. -->

Сервер VP8 переиспользует буферы зашифрованных записей и RTP-фрагментов.
Настройки клиента, ссылки, ключи и wire format остаются прежними.
Новые параметры конфигурации не требуются.

## Владение буферами

`transport.CopyingSender` - необязательный контракт: после возврата Send и
реализованных peer/control/lane отправок транспорт больше не использует входной
slice, включая возврат с ошибкой. Контракт включён только для серверного VP8:
его KCP-пути копируют сообщение до возврата. Muxconn берёт независимый буфер
на каждую запись и возвращает его после отправки. Большие буферы не остаются
в пуле. Асинхронные транспорты и обёртки без этого контракта сохраняют
прежнее выделение буфера, поэтому очередь не получает изменённые данные.

Серверный payloader VP8 хранит ограниченный scratch на трек. PictureID,
descriptor и границы RTP совпадают с Pion. Общий writeMu действует до завершения
записи во все bindings; pacer и стандартный NACK cache хранят собственные копии.
Клиентский payloader продолжает использовать прежнюю реализацию Pion.

Повторно отложенный KCP-пакет того же SN обновляется в собственном буфере.
Свежие TS/UNA и срок отправки сохраняются. ACK и flush удаляют запись как прежде;
нового кэша пакетов нет.

## Переподключение VK

Полная попытка подключения и переподключения ограничена минутой и более ранним
deadline вызывающего контекста. Бюджет охватывает обновление credentials и
ожидание SERVER topology. Если обе попытки набрать дополнительных гостей
завершились ошибкой, управление возвращается supervisor для повтора с backoff.
Если гости присоединились, ожидание переключения остаётся в общем бюджете.

Запись сигналинга ограничивает также ожидание writer и саму запись в сокет.
Отмена закрывает сокет и освобождает заблокированный writer. Graceful hangup
имеет короткий предел и пропускается при занятом writer. Close отменяет
незавершённое подключение и освобождает сигналинг и media generation.
Ошибки нового поколения во время reconnect callback сохраняются; закрытое
старое поколение не запускает лишнее переподключение.

Проверки охватывают расшифровку конкурентных записей, асинхронное владение,
PictureID и MTU, несколько bindings и настоящий NACK старого кадра после reuse,
cleanup KCP, blackhole сигналинга и восстановление после отказа recruits.
Результат микробенчмарка отдельной функции не определяет прирост WAN.

# Кэш разбора RTCP в VK Calls

<!-- // ai-generated: describe the RTCP cache boundary, ownership and regression checks. -->

В Pion interceptor v0.1.45 статистика использует входные attributes, хотя нижний
reader может вернуть другую карту с уже разобранным RTCP. Когда входная карта
nil, каждый recorder создаёт собственный кэш и повторяет разбор для своего SSRC.
В WAN-профиле TransportLayerCC.Unmarshal занимал около трети временных выделений.

Последним в цепочку VK добавлен rtcpCache. Перед каждым Read он создаёт карту,
если вызывающий её не передал. Эта карта доступна всей цепочке, включая stats
и NACK. Входная карта вызывающего сохраняется. Общего кэша между чтениями нет:
следующий пакет получает новую карту и не использует результат предыдущего.
Адаптер не разбирает и не фильтрует пакеты, сохраняет ошибки и число прочитанных
байт. Версии зависимостей и wire protocol не меняются.

Порядок регистрации существенен: последний interceptor первым получает вызов
Read и передаёт attributes внутрь. Добавление rtcpCache до stats не исправляет
повторный разбор, потому что входной аргумент stats останется nil.

TestRTCPStatsSharePacketCache проверяет общие объекты пакетов у четырёх SSRC,
атрибуты вызывающего и новый кэш при следующем чтении. TestRTCPCacheReadError
проверяет ошибки. TestRTCPCacheAnswersNACK запрашивает реальную повторную отправку
через стандартную цепочку Pion. BenchmarkRTCPStatsCache сравнивает разбор TWCC
со 128 дельтами для четырёх SSRC; это микробенчмарк, а не оценка скорости WAN.

Старый клиент работает с новым сервером без обновления. Клиентский бинарник,
ключи и профиль при серверном выпуске сохраняются.

Отдельно серверный путь VK запрашивает приёмный UDP-буфер 1 MiB: потери сокетов
сохранялись после устранения повторного разбора. Бюджет проходит через конфигурацию
ссылки в ProtectedNet и применяется к UDP ListenPacket, ListenUDP, Dial и DialUDP.
При отказе SetReadBuffer соединение сохраняется, ошибка записывается в журнал.
Другие экземпляры адаптера и TCP не меняются. Клиент оставляет бюджет нулевым,
сохраняя платформенный размер. На Linux ядро обычно показывает удвоенное значение
SO_RCVBUF; фактический размер также ограничен системным rmem_max.
Тест TestProtectedNetUDPReadBudget проверяет реальные сокеты четырёх путей.
Окна KCP и настройки ядра выпуск не меняет.
